## 1. 策略一句话

在 BTCUSDT、ETHUSDT 现货上，用**有限层数（最多 9 层）、动态倍数加仓（1.2～1.5，按组回撤分档）**的网格马丁做“经常小赚”，核心是活得久：只在震荡市开新组，下跌时按 ATR 间距逐层加仓（加仓受趋势状态过滤：强势下跌暂停、缓慢下跌限速），每层独立止盈回上一层触发价，整组浮盈 +1.5% 就全卖（反弹状态收紧至 +0.8%）；用 −20% 停加仓、7 天减半 / 14 天清仓、15% 回撤 halt 三道硬线兜底。不用杠杆、不做空、不做合约。

## 2. 策略详解（与 SPEC §1–§5 对照）

### 2.1 网格组（grid group）

- 一个“组” = 一次开仓决策产生的一篮子分层买单。**单币种同时只能有一个 OPEN 组**；BTC 组与 ETH 组相互独立，但合计已部署受共同上限约束。
- 开组即买第 1 层：以当时 last 价买入第 1 层名义，成交价记为**中心价 C**，组内 C 永不改变。开组时算一次间距 `d`，组内不变。
- 不存在 0 持仓的 OPEN 组：第 1 层取整后名义 < 5 USDT、或买入后违反合计上限时，**不开组**，只记 WARNING。

### 2.2 间距与触发价（SPEC §3.2）

间距由开组时刻的 ATR(14, 1h) 决定：

| 币种 | 公式 | 钳制 |
|---|---|---|
| BTC | `d = 2.0 × ATR / C` | `[0.8%, 3.0%]` |
| ETH | `d = 2.5 × ATR / C` | `[1.0%, 4.0%]` |

第 n 层触发价：`trigger(n) = C × (1 − (n−1) × d)`，n=2..9；第 1 层触发价即 C。边界：d 较大时第 9 层触发价可能 ≤ 0.80C（例如 ETH d=2.5% 时 L9 触发价恰为 0.80C），此类层永不买入（停加仓线先触发），组最多 8 层——这是 SPEC 已披露的边界效应，不是 bug。

买入条件（每轮按层号从小到大判断）：当时 last 价**严格小于**触发价（等于不触发）；且第 1..n−1 层曾经买入过（状态 OPEN / SOLD / TIME_STOPPED 任一）；且第 n 层仍为 PENDING；且未触发停加仓；且满足上限。**同轮跌破多层时依次买齐**，每买一层立即更新现金与已部署，再判断下一层。已 SOLD 的层在本组内不重新买入。

### 2.3 层名义与加仓倍数（SPEC §2）

- 初始本金 10,000 USDT；BTC 上限 3,000，ETH 上限 2,000，**合计已部署上限 5,000（固定值，不随权益浮动）**，其余 5,000 始终为现金预留。
- 加仓倍数**动态**（v5.7）：按触发轮的组回撤 DD 分档——DD<2% → 1.2；2–5% → 1.3；5–10% → 1.4；10–20% → 1.5（仅当非 STRONG_DOWN）；DD>20% 停加仓。同轮多层共用同一 DD 档位。**递归基数是上一层的计划名义**（D-1 裁决）：`planned(n) = planned(n−1) × 档位倍数`；上限截断与步长取整只影响当层实际成交，永不污染递归。计划名义持久化在 `layers.planned_notional_usdt` 列，重启后从该列恢复；该列为 NULL 时记 ERROR + 停加仓，**绝不用实际名义反推**。
- 均匀 1.3× 参考名义（用于压力测试解析值与 L1 种子）：`layer(n) = round_half_up(cap × 1.3^(n−1) / S9, 2)`，其中 `S9 = 1 + 1.3 + … + 1.3^8 = 32.01499791`；第 9 层用残差法使 9 层合计严格等于上限。**下表是权威值**，重算有出入时以表为准：

| 层 | BTC（cap 3,000） | ETH（cap 2,000） |
|---|---|---|
| L1 | 93.71 | 62.47 |
| L2 | 121.82 | 81.21 |
| L3 | 158.36 | 105.58 |
| L4 | 205.87 | 137.25 |
| L5 | 267.63 | 178.42 |
| L6 | 347.92 | 231.95 |
| L7 | 452.30 | 301.53 |
| L8 | 587.99 | 391.99 |
| L9（残差） | 764.40 | 509.60 |
| 合计 | 3,000.00 | 2,000.00 |

- 上限校验用**实际成交名义（basis = qty × buy_price）**，不用计划名义；已部署口径 = Σ(OPEN 层 basis)，不含手续费与滑点。
- 数量 = 层名义 / 成交价，按最小步长**向下取整**（BTC 0.001、ETH 0.01）；取整后名义 < 5 USDT 的层跳过，金额不累到下一层。
- 上限拒买时：该层置 CANCELLED、组 `stop_adding=1`、其余 PENDING 层一并 CANCELLED，只记一次 ERROR，不再重试。

### 2.4 卖出（SPEC §3.3）

- **单层止盈**：Ln 的止盈价 = 上一层触发价，即 n≥2 时 `TP(n) = C × (1 − (n−2) × d)`，L1 的止盈价 = `C × (1 + d)`。last 价 `>=` 止盈价时卖出该层全部数量（等于触发）。同轮多层达标时**全部卖出**。
- **整组止盈**：last 价 `>=` 剩余 OPEN 层的加权平均成本 × 1.015 时，卖出组内全部剩余 OPEN 层并关组；**REBOUND 状态下系数收紧为 1.008**（+0.8%）。平均成本只算剩余 OPEN 层，不含已卖出的层与手续费。
- **关组规则**：OPEN 层数变为 0 且至少买入过 1 层时，立即置 CLOSED；剩余 PENDING 层在同一事务内置 CANCELLED。`close_reason` 映射定死：整组止盈 → TAKE_PROFIT；单层止盈卖空 → ALL_SOLD；7 天减半卖空 → TIME_STOP_7D（优先于 ALL_SOLD）；14 天 → TIME_STOP_14D；halt → DRAWDOWN_HALT；版本切换过渡平仓 → TRANSITION_CLOSE（见 §2.6 末）。

### 2.5 开新组过滤：只在震荡市开仓（SPEC §4.1）

以下 6 条**全部满足**才能开新组（任一不满足只禁开组，不影响已有组的卖出）：

1. ADX(14, 1h) < 25（严格小于，取上一根已收盘 K 线的 ADX）。
2. 上一根已收盘 K 线 close 严格满足 `LL_480 < close < HH_480`（HH/LL 取最近 480 根已收盘 K 线，含比较对象那根；收出 480 根内新高/新低即视为突破，不满足）。
3. 当前 ATR(14) < 过去 20 日（480 根）ATR 中位数的 2.0 倍（严格小于）。
4. 未来 24 小时且过去 2 小时内无高影响事件（`data/events.csv` 中 impact=HIGH 的 CPI / 非农 / FOMC 决议），区间为 `(now−2h, now+24h]`；事件日历 stale（最后一条事件 < 当前时间 + 90 天）时同样禁开新组。
5. 账户未触发 §5 的停手状态（halt 未到期、日亏损未触发）。
6. 该币种无活跃组，且买入第 1 层后仍满足合计上限。

### 2.6 趋势状态与事中保护（SPEC §4.3、§4.2、§5）

- **趋势状态分类（v5.7 新增 §4.3，优先级瀑布，每轮按币种算一次）**：① **STRONG_DOWN**（ADX≥25 且 −DI>+DI 且 RET24≤−5%）→ 暂停加仓（卖出不受影响）；② **SLOW_DOWN**（ADX≥25 且 −DI>+DI）→ 每组每滚动 24 小时最多加仓 1 次（冷却读 `MAX(bought_utc)`，仅看 layer_no≥2 的已买入层，L2 首加豁免；边界 `≥86400s` 准买）；③ **REBOUND**（ADX<25 且 RET24≥+3%）→ 整组止盈系数 1.5%→0.8%；④ **RANGING** 默认。**REVERSAL 只是状态转移标签**（上一轮 STRONG_DOWN/SLOW_DOWN → 本轮非此二态时记一轮），无独立机制、不影响交易。**已开的组永不重新锚定中心价**（D-9）。RET24 = 上一根 close / 25 根前 close − 1（仅已收盘 K 线）；+DI/−DI 为 Wilder 计算的暴露值。已知语义怪点：ADX≥25 的上升趋势会落入 RANGING（瀑布前三项都不满足），SPEC 已披露，不影响交易逻辑。
- **停加仓线 −20%**：last 价 `< C × 0.80`（严格小于）时，组 `stop_adding=1` 并持久化，未买的层全部 CANCELLED；**价格反弹也不恢复加仓**。已有持仓继续按 §5 卖出。注意边界：间距 d 较大时第 9 层触发价可能 ≤ 0.80C，此类组永远买不满 9 层（见 §2.2）。
- **时间止损**（从 `first_buy_utc` 起算）：满 7 天且未执行过减半时**只执行一次**——从最高层号的 OPEN 层往低层号整层卖出（不拆层），直到累计卖出的初始层名义 ≥ 当前全部 OPEN 层初始名义之和的 50%；仅 1 层 OPEN 时卖出该层并关组；执行后 `half_time_stopped=1`、`stop_adding=1`；卖出的层记 TIME_STOPPED。满 14 天时卖出全部剩余持仓并关组。
- **满层豁免 holdmax（v5.6 新增，v5.7 延至 9 层）**：`bought_layers = COUNT(层状态 ∈ {OPEN, SOLD, TIME_STOPPED})`；当 `bought_layers == 9` 时，该组**跳过 7 天减半与 14 天清仓**（不执行、不记 half_time_stopped、不置 stop_adding），继续持有直到止盈或 halt。**只豁免时间止损，不豁免止盈与 halt。**满层组没有新的时间止损接替，持有期无上限，资金持续占用，且该币种不开新组。
- **版本切换过渡平仓（v5.7 切换时一次性，SPEC §9 第 18 条裁决 (d)）**：v5.7 代码首次启动时，若库中有 v5.6 遗留 OPEN 组（层数 ≤6），按市价卖出其全部 OPEN 层（`TRANSITION_CLOSE`）、PENDING 层置 CANCELLED、组置 CLOSED；**现金与已实现盈亏结转、账户不重置**；幂等（CLOSED 组不重复触发）。接线在 `monitor.py` 的 `main()` 内、`startup_checks()` 之后、首轮之前（2026-11-12 补接线修复轮补入，见 `results/fix_audit_v57.md`）。切换当日实测：BTC 组 1 的 2 层与 ETH 组 2 的 5 层被平仓，7 笔 TRANSITION_CLOSE，现金 8,111.08→9,934.01。
- **账户回撤 halt 15%**：权益相对历史峰值 `peak_equity`（只升不降，持久化）回撤 `>= 15%` 时触发。触发后先在独立事务里置 `halt_state=HALTING` 并提交，再按 symbol 升序、layer_no 升序**逐层卖出、每层一个独立事务**并记 durable 进度，全部卖完后在最终事务里置 HALTED、`halt_active=1`、冷静期至触发时刻 +24 小时。HALTING 中途失败保持 HALTING，下一轮或重启后续清；连续 3 轮零进展则停新交易等人工处理，但每轮仍尝试续清。冷静期满恢复时峰值重置为**本轮估值价算出的当前权益**，恢复那一轮跳过 §5.1 检查。
- **每日亏损上限**：当日亏损（权益 − 当日 UTC 00:00 权益）`< −300 USDT`（严格小于）时，当日禁止开新组与加仓，已有持仓继续卖出；次日 UTC 0 点自动解除。
- **每轮处理顺序（SPEC §5.0，定死）**：(0) HALTING 续清守卫 → (a) halt 期满恢复 → (b) 回撤 halt 判断 → (c) 按优先级执行组内退出：① halt ② 14 天 ③ 整组止盈 ④ 7 天 ⑤ 单层止盈（同一轮同一组多个条件满足时只执行第一个，单层止盈除外：多层达标全卖）→ 最后判断买入（开组/加仓）。日亏损只禁买入，不参与退出优先级。

### 2.7 成本与会计口径（SPEC §1.3、§1.4）

- 买卖价 = 当时 last 价（回测中 = 当根 K 线 close），**不做价格偏移**。手续费 = 成交名义 × 0.10%，滑点 = 成交名义 × 0.02%（**单独现金扣款，不调整成交价**）。单边总成本 0.12%。
- 现金：买入扣 名义 + 手续费 + 滑点；卖出加 名义 − 手续费 − 滑点。持仓成本 basis = qty × buy_price（不含手续费与滑点）。权益 = 现金 + Σ(OPEN 层 qty × last 价)。已实现盈亏按卖出层记 `(sell − buy) × qty − 买卖双边手续费与滑点`，买入费用取 layers 表记录值，不许重算。
- **现金不变量（单测必须断言）**：`cash = initial + realized_pnl − Σ(OPEN 层 basis) − Σ(OPEN 层买入费用)`。违反即会计 bug。
- **每轮单一估值价**：每轮开始时固定一个估值价（接受的有效价，或可疑/无效时的上一轮有效价），本轮全部决策与写入共用该价，不许中途换价。

### 2.8 价格异常状态机（SPEC §4.2、§7）

- **有效价**：HTTP 200、价格 > 0、服务器时间与本地 UTC 偏差 ≤ 60 秒。服务器时间取本轮 `GET /api/v3/time` 的 serverTime，失败时读 ticker 响应的 HTTP Date 头，两者都拿不到则该轮价格无效。**注意 `GET /api/v3/ticker/price` 只返回 symbol + price，不含 serverTime。**
- **可疑价**：有效价较上一轮有效价跳变 `> 10%` 时记为可疑价，存入 `symbol_state.last_suspect_price`。可疑价当轮**禁止开组/加仓、跳过止盈**，估值与 halt 判断用上一轮有效价（halt 判断必须执行，不许跳过）。
- **接受条件（二选一）**：(a) 下一轮价格 P2 与可疑价 P1（取持久化的 `last_suspect_price`）同向（相对上一轮有效价同涨同跌）且 `|P2−P1|/P1 ≤ 15%`——满足时 P2 **当轮即被接受**为有效价，正常参与本轮决策；(b) 可疑价当轮用最近一根已收盘 K 线 close 佐证，偏差 ≤ 5% 则接受——但当轮决策仍用旧价，被接受的价格从下一轮起成为新有效价。接受后 `suspect_price_streak` 清零，`last_suspect_price` 置 NULL。
- **计数与恢复**（按币种独立，存 `symbol_state` 表）：`price_error_streak`（连续拿不到有效价）与 `suspect_price_streak`（连续可疑价）任一 ≥ 3 时，停开仓/加仓、止盈跳过、halt 用上一轮有效价；streak < 3 时读到一次正常有效价（跳变 ≤ 10%）立即清零对应 streak；一旦 ≥ 3，必须 `recovery_streak ≥ 3`（连续 3 轮正常读价）才同时清零两者；恢复期内任何一轮未拿到正常有效价，`recovery_streak` 清零。重启后 streak 从库恢复，不清零。

## 5. 模块指南（给要改代码的 AI）

### 5.1 `config.py`：唯一配置来源

- 不读环境变量，不读其他配置文件。`EXECUTION_MODE` 是常量 `"DRY_RUN"`，不许改成其他值。
- `verify_frozen_config()`：逐项比对当前模块属性与 `FROZEN_VALUES`（**类型也要相同**，`25` 与 `25.0` 算不符），并用 half-up 公式重算层名义、校验合计等于上限。`backtest.py` 的 `main()` 在启动时调用它，不通过即 `sys.exit(1)`。
- 公共行情端点（无 Key）：主 `https://data-api.binance.vision`，备用 `https://api.binance.com`。

### 5.2 `engine.py`：共享逻辑（monitor 与 backtest 共用部分定义，但回测有自己的引擎，见 §5.4）

- **Schema（`SCHEMA_SQL`，WAL 模式）**：`account`（单行 id=1，现金/峰值/halt 状态/日初权益/last_equity/last_poll/已实现盈亏）、`symbol_state`（分币种价格与 streak）、`grid_groups`（组，`symbol + status='OPEN'` 唯一索引保证单币种一个活跃组）、`layers`（层，`(group_id, layer_no)` 唯一）、`trades`、`daily_summary`、`risk_events`、`regime_log`。字段全集见 SPEC §6.1，`engine.py` 的建表语句即权威实现；v5.7 新增 `layers.planned_notional_usdt` 列与 `regime_log` 的 regime/ret24_pct/plus_di/minus_di 列，`init_db` 迁移经 `PRAGMA table_info` 预查、幂等（A-6 已确认）。
- **指标（`calculate_indicators`，只用已收盘 K 线，不足 500 根返回 None 并禁开新组）**：TR 定义含首根无 prev_close 的退化；ATR(14) 为 TR 的简单平均，第一个 ATR 值在第 14 根；ADX(14) 为 Wilder 平滑（α=1/14），平滑 TR/±DM 的种子为下标 1..14 的 14 个值之和（下标 14 处），DX 由 +DI/−DI 算出，第一个 ADX 值为下标 14..27 的 14 个 DX 的平均（下标 27，即第 28 根）；HH_480/LL_480 与 ATR 中位数取最近 480 根（偶数个，中位数取中间两数平均）；`in_range` 为严格不等式。**+DI/−DI 已暴露**（v5.7）：`calculate_indicators` 返回 `plus_di`/`minus_di`/`ret24`，K 线不足 500 根的早退字典同样补齐三键为 None（补接线修复轮 A-3）；`ret24` 计算有 `closes[-25] != 0` 守卫（A-4）；`tr_val == 0` 时 ±DI 置零（A-5 已确认）。
- **事件日历（`load_events_calendar`）**：读版本头 `# version: …, sha256: …`，对剔除版本头后的正文（去 BOM、CRLF→LF、末尾换行原样保留）实算 sha256 并与版本头比对，不符即报错；校验表头、4 列、impact 枚举、时间升序、无重复。`check_event_filter`：只看 impact=HIGH 的事件；stale 定义为最后一条事件 < 当前时间 + 90 天。
- **下单与会计**：`compute_order_qty` 按步长向下取整并返回实际名义（保留 4 位小数）；`assert_cash_invariant` 校验现金不变量（容差见 §7 注意事项）；`compute_grid_spacing` 用配置系数与钳制（**其 docstring 写的 1.5/2.0 是旧版残留，以 `config.py` 的 2.0/2.5 为准**）；`compute_trigger_price` / `compute_tp_price` 实现 §3.2/§3.3 公式。

### 5.3 `monitor.py`：实时模拟盘

- `BinancePublicClient`：`urllib` 实现，只调公共接口——`GET /api/v3/time`（服务器时间）、`GET /api/v3/ticker/price`（last 价）、`GET /api/v3/klines?interval=1h`（最近 500 根**已收盘** K 线，不含当前未收盘的那根）。主/备用端点切换在 `_fetch_json` 内处理。
- `SpotMartingaleMonitor.poll_once(now_utc, now_monotonic)`：每轮先固定单一估值价，再按 SPEC §5.0 顺序执行（HALTING 续清 → halt 恢复 → halt 判断 → 组退出/加仓 → 开新组评估），最后 `_end_round_bookkeeping` 写 last_equity / peak / daily_summary。`_process_group_exits_and_adds` 实现退出优先级与加仓；`_consider_open_new_group` 实现 §4.1 六条件并写 `regime_log` 与 `REGIME_BLOCK` 风险事件；`_execute_halting_sweep` / `_liquidate_layer` 实现 halt 逐层清仓。
- 启动检查（`startup_checks`）含事件日历加载与配置校验；随后 `main()` 调用 `execute_transition_close()`（过渡平仓接线，v5.7 补接线修复轮补入，**不在** `startup_checks()` 内部）；日志同时写 stdout 与 `logs/spot_YYYYMMDD.log`（UTC 日期）。**没有 watchdog、没有 systemd service**：进程退出后保持退出，等人工处理；重启后按 §6.1 从库恢复全部状态，先续清 HALTING、再判断 halt 恢复。**注意**：`import monitor` 时即创建 `logs/` 下的 FileHandler，`logs/` 目录不存在会直接报 FileNotFoundError——新环境先 `mkdir logs`（单测与回测复现时同样需要）。
- 命令行：`python3 monitor.py`（无限轮询，60 秒一轮）、`--once`（单轮）、`--rounds N`（N 轮后退出）、`--db PATH`（指定数据库路径，补接线修复轮新增）。**警告：运行 monitor 会在 `data/` 下创建/读写 `spot_martingale.sqlite3` 并写 `logs/`；实验前请先复制整个仓库，不要在唯一一份数据上试。**

### 5.4 `backtest.py`：离线回测（不连实时行情）

- **数据清洗（`load_cached_klines`）**：仅保留 open_time 为 UTC 整点且 OHLC 均为有限正数的行；按 open_time 升序去重（重复只留首行并记 WARNING）；不能映射到整点网格的记录单独记数据质量计数，不计入价格错误轮。本仓库数据实测：两币种各 51,629 根有效 bar，unmappable=0、dups=0、all_invalid=0。
- **撮合：close-only。** 每根 1h K 线只在收盘时刻用 close 价判断一次，顺序为 HALTING 续清 → halt 恢复 → halt 判断 → 退出（按 §5.0 优先级）→ 买入；**不用 low/high，不猜盘中顺序**。回测粒度比实盘 60 秒轮询粗，是已知局限。
- **整点网格**：按评估窗口的起止 UTC 整点逐小时推进；网格内无 bar 的小时计一次价格错误（该币种当轮不交易，halt 与时间止损仍按上一轮有效价评估）；指标在有效 bar 序列上连续计算（跨缺口不重置）。
- **价格状态机**：回测同样执行 §4.2（含 streak 与接受条件）。窗口开始前用 start_dt 前最近一根有效 bar 的 close 做**预热初始化**（须在 24 小时内，否则走回退路径：首根有效 bar 所在轮初始化、不计价格错误，即 P-1 裁决）；条件 (b) 的参考价定义为**上一根**已收盘有效 K 线的 close（`latest_kline_close` 参数无默认值，每轮须显式传入），不得用当根 close（否则条件 (b) 恒成立）。每个窗口独立重置全部状态。
- **分区**：训练集 2021-01-01T00:00Z 至 2024-12-31T23:00Z（35,064 小时）；测试集 2025-01-01T00:00Z 至 2026-10-31T23:00Z（16,056 小时）；压力测试 4 为真实切片 2022-06 全月（720 小时），策略正常跑。
- **压力测试 1–3 是确定性持仓测试，不是策略模拟**：第 0 小时视为两币（或单币）各 9 层已按固定间距触发价买入（间距取配置值除以 100：BTC 0.020、ETH 0.025；层名义用均匀 1.3× 表），720 个整点步按几何路径走（+50% / −50% / 先 −30% 后 +20%），**期间不执行止盈与时间止损，只执行 halt**；−50% 双币情形 halt 后 24 个整点步执行恢复并验证峰值重置，恢复后不再开新组。ST2 单币解析值：BTC −1,310.02、ETH −834.66（合计 −2,144.68，为无 halt 时的满跌浮亏）；双币实测 halt 在第 509 小时、落地 −1,504.42。峰值硬规则（D-8）：第 0 小时峰值固定为 10,000，市价权益 10,716.64 不抬峰值。
- **指标口径（`get_metrics`，与 SPEC §8.3 一致，务必区分）**：`total_pnl = 期末权益 − 初始本金`（**含未平仓组浮亏**）；最大回撤按每步记录的峰值算，同时报告收盘采样回撤与 halt 落地后回撤；**利润因子只算 SELL 成交的已实现盈亏**（盈利和 / 亏损绝对值和），无 SELL 时记 0.0；**盈利月占比只算有 ≥1 笔 SELL 成交的自然月**，分子为其中已实现盈亏 > 0 的月数。这就是 v5.6 测试集利润因子 14.83 但总盈亏为负的原因：两者口径不同（见 `RESULTS.md` §2）；v5.7 测试集 PF 1.10 与总盈亏 −471.96 同样口径不同。
- **`main()` 固定跑全套**：训练 + 测试 + 压力测试 1–4 + §8.3 验收评估。`--all` 参数存在但**不改变行为**（无分支判断），直接 `python3 backtest.py` 即全套。验收第 6、7 项只打印提示语（单测与复现性需另行运行验证）。

## 7. 给下一个 AI 的注意事项（坑位清单）

1. **过期 docstring**：`engine.py` 的 `compute_grid_spacing` docstring 仍写 BTC 1.5 / ETH 2.0（v5.5 旧系数），代码实际读 `config.py` 的 2.0 / 2.5——**以 config 为准**。`monitor.py`、`backtest.py`、`config.py` 头部的 “Frozen under SPEC v5.1” 同样是旧版残留，代码实际执行 v5.7（含 9 层、动态倍数、趋势状态与 holdmax）；`python3 config.py` 打印的 “SPEC v5.1” 也是同一类残留文字，校验本身按当前 `FROZEN_VALUES` 执行。不要按 docstring “修复”代码。
2. **现金不变量容差**：`engine.py` 的 `assert_cash_invariant` 注释写容差 0.005，实际判断是 `diff > 0.01` 才报错。两者都是“近似为零”的工程容差，改动前先确认 SPEC 是否有数字要求（SPEC §1.4 只写等式，未写容差）。
3. **`regime_log` 在 v5.7 是每轮心跳**：趋势状态每轮都算、每轮都写（两币种各一行，含 regime/ret24/±DI）；v5.6 及之前只在开新组评估轮写入。判断 monitor 是否存活仍看 `account.last_poll_utc`（最稳），`regime_log` 最新时间戳也可作参考。
4. **+DI/−DI 已暴露（v5.7）**：`engine.py` 与 `backtest.py` 的 ADX 计算都返回 +DI/−DI 与 RET24，两处定义须保持一致；K 线不足时的早退字典同样含三键（None），下游不得假设键缺失。
5. **利润因子与总盈亏口径不同**：PF 只看已平仓 SELL，总盈亏含未平仓浮亏。v5.6 测试集 PF 14.83 与总盈亏 −173.45 同时成立，不矛盾。引用数字时必须注明口径。
