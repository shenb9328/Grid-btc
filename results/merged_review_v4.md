## 二、Muse 自查裁决

### 1. Codex 的 headline 指控不成立（已复算）

Codex 称 §8.2 三种起始现金只扣了 0.10% 手续费、漏扣 0.02% 滑点，双币现金应为 4,993 而非 4,994，起始权益 9,993 而非 9,994。

**复算（按 §1.3：费 = 名义 × 0.10%，滑点 = 名义 × 0.02%，买入时现金扣名义 + 费 + 滑点）：**

| 情形 | 费 | 滑点 | 合计 | 现金 = 10,000 − 名义 − 合计 | SPEC 写的值 |
|---|---|---|---|---|---|
| BTC 3,000 | 3.00 | 0.60 | 3.60 | 6,996.40 | 6,996.40 ✓ |
| ETH 2,000 | 2.00 | 0.40 | 2.40 | 7,997.60 | 7,997.60 ✓ |
| 双币 5,000 | 5.00 | 1.00 | 6.00 | 4,994.00 | 4,994.00 ✓ |

双币起始权益 = 4,994 + 5,000 = 9,994，回撤 = 6/10,000 = 0.06%，SPEC 数字全部正确。

Codex 的 4,993 对应总成本 7.00，即费率 0.14%——它是把 0.12% 的单边总成本误当成手续费、又加了一次滑点，重复计了。**agy 的第 7 项也核过同一组数（9,994 / 0.06%），与 SPEC 一致。**Codex 的 FAIL 结论第一条理由被推翻；其 FAIL  verdict 因此不成立，剩余问题见下。

（注：agy 第 7 项把 6.00 写成“买入手续费”是措辞不严——6.00 是费 5.00 + 滑点 1.00——但数字与 SPEC 一致，不构成问题。）

### 2. 剩余真实缺口（6 项，无架构 blocker）

#### [P1-小] HALTING 零进展计数未持久化（Codex A4 / B P1-3，属实）
§5.0/§5.1 定义了“连续 3 轮零进展”，但 §6.1 account 表里没有这个计数字段，重启后是延续还是清零也没定义。人工重启可能反复归零计数，绕过 3 轮上限。
**补法**：account 表加 `halt_zero_progress_rounds`（INTEGER，默认 0）；HALTING 轮未成功卖出任何一层时 +1，成功卖出任何一层时清零；重启时从库恢复、不重置。

#### [P2] 单一估值价与无效价跳过的张力（Codex A10 / B P1-2，属实）
§1.4 说“本轮全部决策与写入共用该价”，§4.2/§7 又说无效价轮止盈跳过、halt 用上一轮有效价。两处都没写清单价规则与跳过规则的分工。
**补法**：一句话定死——单价规则只约束“执行中的决策用哪个价”，跳过规则决定“哪些决策执行”。无效价轮：止盈跳过；halt 用固定价评估；时间止损（7d/14d）是时间到期型退出，仍按固定价评估并执行（卖出价 = 固定价）。

#### [P2] 可疑价读写顺序 + 条件 (a) 当轮生效（agy #3 / Codex A3，属实）
v4 一处写“每轮可疑都更新 last_suspect_price”，另一处写条件 (a) 用持久化的 P1 算 |P2−P1|/P1。实现时先写后读会拿 P2 和自己比（恒通过）。另：条件 (a) 在第 2 轮满足时，当轮是否立即用 P2 正常交易未写清（只写清了条件 (b) 的时点）。
**补法**：读到跳变 >10% 的新价 P2 且已有 last_suspect_price（P1）时，**先**用 P1 判条件 (a)；通过则当轮即接受 P2 为有效价，正常参与本轮估值/决策；(a)(b) 都不满足才用 P2 覆盖 last_suspect_price 并按可疑价限制当轮交易。

#### [P2] recovery_streak 边界（agy #2 / Codex A2 + B P2-1，属实）
恢复期内读到一个未被接受的可疑价（HTTP 200、跳变 >10%）既不算“失败”也不算“正常读价”，recovery_streak 是清零还是保持未定义；“streak ≥ 3”也没写清是指哪个 streak。
**补法**：进入恢复计数期的条件是 `price_error_streak ≥ 3 OR suspect_price_streak ≥ 3`；恢复期内任何一轮未拿到“跳变 ≤10% 的正常有效价”（HTTP 失败或未接受的可疑价），recovery_streak 均清零；满 3 轮正常读价后同时清零两 streak 并将 last_suspect_price 置 NULL。

#### [P2] sha256 字节规范仍不完全（Codex A9 / B P2-2，属实）
§1.1/§7 写了 UTF-8、LF，但没规定 CRLF 输入如何转 LF、是否允许 BOM、末尾换行怎么处理，生成端与校验端仍可能算出不同哈希。
**补法**：生成与校验同口径——先去文件首部 UTF-8 BOM（若有），正文 CRLF→LF 归一化；末尾换行原样保留（不增不删）；哈希算在归一化后的字节上。

#### [P3] 冻结值表缺恢复阈值行（Codex A8，属实但轻微）
表里已有“异常连续次数 3 次”，但恢复所需“连续 3 次正常读价”没单独成行。
**补法**：§7.1 加一行“恢复所需连续正常读价 | 3 次 | §4.2”。
