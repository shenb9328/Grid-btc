## 2. 各自独有的重要发现

### agy 独有
- 现金储备冲突：任何亏损 / 手续费后，“已部署 5,000 + 现金 ≥5,000”不可能同时满足；买满 6 层实付约 5,006.03 USDT，已击穿现金下限。建议改为已部署 ≤ min(5000, 权益×50%)。
- 闪崩跳过风控：价格跳变 >10% 被当“可疑”跳过本轮，§5.1 的 15% 强平也被跳过，等 K 线佐证时跌幅早已远超 15%。
- 事件冷却缺失：只禁“未来 24h 内有事件”，CPI/非农/FOMC 公布后第 1 秒即变为可开仓，应加公布后 2 小时冷却；日历 stale 检查只在启动时，应改为每轮检查。
- ADX 定义缺失：§7 写“K 线不足 15 根算不出”，但 ADX(14) Wilder 至少需 28 根以上才有第一个有效值；且 480 根区间 + ATR 需至少 494 根已收盘 K 线，应改为拉取 ≥500 根。
- 最小下单连锁故障：BTC 价涨到 235,181 以上时第 1 层取整为 0 而被跳过，随后 2–6 层因“前 n−1 层已买入”前提全部无法买入。

### Codex 独有
- P0-9 事件日历回测不闭合：stale 规则若按真实当前日期判断，2021–2026 历史回测无法按历史时点复现；回测事件覆盖、impact 映射均未定义。
- P1-6 / P1-7：DB 缺唯一约束、事务边界、中断恢复规则；SQLite 锁、损坏判定、首次建库条件未定义。
- P1-8：看板只读隔离验收不清：mode=ro 与 monitor 并发写入时的锁 / 读失败行为未定义。
- P1-12：DRY_RUN 配置来源与默认值矛盾，“除开关外可用环境变量改阈值”有歧义。
- P1-13：watchdog 责任空缺：v0 说不建 service，又说“由外部 watchdog 决定是否重启”，但 watchdog 是否存在未说明。
- P1-14：“测试集只跑一次”适用范围不明：压力测试、单元测试、修复后重跑是否受限未说清。

## 3. Muse 自查：两处需要纠正 / 降级的评审意见

1. **Codex P0-7“第六层触发价为负值”——降级，不成立。** 在 SPEC 的钳制范围内，BTC 最大间距 3% 时第六层为 0.82C，ETH 最大间距 4% 时为 0.76C，均为正数；只有间距 >16.7% 才会为负，而间距已被钳制。Codex 自己在算术小结里也承认“仍为正数”。真正的问题是“第六层之后价格继续下跌如何处理”未定义，应降为 P1，v1 中补定义。
2. **agy“BTC 单边 −50% 亏损仅约 1,400，根本触发不了 15% 回撤”——对单币成立，对组合需注记。** Muse 复算：BTC 满仓 6 层、价格跌到 0.50C，亏损约 1,397 USDT（<1,500）；ETH 同理约 906 USDT；**两币同时满仓则合计约 2,303 USDT，已超过 1,500**。SPEC §8.2 没写清压力测试是单币还是组合，这是 v1 必须补的定义；但验收第 5 条的自相矛盾本身不受影响（触发后平仓成本仍使落地回撤 >15%）。

其余 P0/P1，Muse 复算后均确认成立，未发现评审在算术上算错的地方。

## 4. v1 必须修的清单（合并后，按严重程度）

MUST-FIX（不修不能冻结）：
1. 权益公式改为 现金 + 持仓市值（删 −未实现亏损），并定义估值价、手续费入账、峰值生命周期与重启恢复；halt 恢复时重置峰值权益（或引入独立回撤基准）。
2. 重写 §8.3 第 5 条：去掉“halt 必须触发且最大回撤 ≤15%”的不可能要求，改为“触发时平仓、落地回撤 ≤15% + 跳空与成本容差”，并写清压力测试是单币还是组合、精确起止 UTC。
3. S 更正为 12.75603；层名义唯一公式定死为 round(cap × 1.3^(n−1) / S, 2)，BTC 各层 235.18 / 305.74 / 397.46 / 516.70 / 671.71 / 873.22（合计 3000.01，第 6 层改用残差法使合计严格等于 3000.00），ETH 各层 156.79 / 203.83 / 264.97 / 344.46 / 447.80 / 582.15（合计 2000.00）。
4. 成本模型二选一：直接取 last 价 + 0.10% 手续费 + 0.02% 滑点（合计单边 0.12%），或换 bookTicker 取真实 bid/ask 并取消 last×(1±0.0002)；写清滑点是价格调整还是单独扣款、现金与持仓成本入账口径。
5. 修网格状态机：开组即买第 1 层（或 X 小时内未触发则自动关空组）；组内 OPEN 层为 0 时立即关组；中间层卖出后能否触发下一层写清；同轮跌破多层是依次买齐还是每轮最多一层；整组止盈优先于单层止盈防双卖；定义第六层后继续下跌的处理。
6. 重写 §4.1.2：用前 480 根已收盘 1h K 线（不含当前根）的 HH/LL，上一根收盘价严格在区间内；定义 ADX 算法（Wilder）与最少 K 线数（≥500 根）；§4.1.3 ATR 中位数定义为 480 个滚动 ATR 值的中位数。
7. 现金储备冲突：已部署 ≤ min(5000, 权益×50%)，上限按实际成交名义（含手续费）计量。
8. 下调 §4.2 单币浮亏停加仓阈值（或改为单币上限的比例）；统一跳变次数（2 次还是 3 次）并定义恢复条件；闪崩时风控强平不得被“可疑价格”跳过。
9. 补 DB 字段：grid_groups 加 first_buy_utc / stop_adding / half_time_stopped；account 加 day_start_equity_usdt / day_start_date_utc / halt_trigger_equity_usdt；layers 状态加 PENDING / CANCELLED / HALT_CLOSED；时间止损 7 天只执行一次，算法定死为从最高层整层往下卖直到累计 ≥OPEN 层初始名义 50%。
10. 补回测定义：1h K 线撮合规则（close 还是 low/high、先买后卖还是先卖后买）、三个压力切片精确起止 UTC、利润因子与盈利月占比的分子分母、回撤采样粒度、事件日历回测版与按模拟时间判断 stale 的规则。
11. 补退出优先级全局规则与状态机：halt / 日损 / 时间止损 / 整组止盈 / 单层止盈的先后顺序、互斥、组状态转移（HALTED vs CLOSED）、重启恢复。
12. 补 DRY_RUN 配置唯一来源与默认值、watchdog 是否存在及责任、“测试集只跑一次”的适用范围、看板只读 API 的 JSON 契约与并发读失败行为。

SHOULD-FIX：事件公布后 2 小时冷却、日历每轮 stale 检查、删未使用的 15m K 线输入、统一时间基准与各阈值边界比较符（< vs ≤）、日亏基准持久化。
