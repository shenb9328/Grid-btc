## 一、Muse 独立核验（自查，评审指控逐条对原文）

以下三条我对着 v3 原文核过，评审说得对，是我的错：

### 1. 时间跳变守卫会把正常轮询误判为跳变（agy P1-1）——成立，我的 bug
- v3 只写“相邻两轮墙钟跳变 >60 秒”，但唯一持久化的时间戳是 last_poll_utc；轮询间隔本身就是 60 秒，正常运行时 `now_utc − last_poll_utc` = 60 秒 sleep + 请求耗时，恒 >60 秒。按字面实现，每一轮都会跳过 halt 期满恢复与 7d/14d 时间止损。
- 正确写法（agy 给的）：跳变判定 = `|(now_utc − last_poll_utc) − Δmonotonic| > 60 秒`，即墙钟增量与单调时钟增量之差。须同时持久化单调时钟读数（或记录期望间隔）。

### 2. streak 清零规则自相矛盾（agy P1-2）——成立，我的错
- v3 §4.2 L150 写“price_error_streak 在任何一次成功读到有效价后即清零（不限于 <3 次还是 ≥3 次）”，L152 又要求异常后需 recovery_streak ≥ 3 才清零恢复。第一次读到有效价就清零后，后面两轮已无从得知处于限权恢复期，3 轮恢复完全失效。
- 正确写法：仅当 streak < 3 时读到正常有效价（跳变 ≤10%）立即清零；一旦 ≥3，必须等 recovery_streak ≥ 3 才清零两者；suspect_price_streak 为 1 或 2 且下一轮价格回到正常范围（相对 last_valid_price 跳变 ≤10%）时立即清零。

### 3. §5.1 L181 残留旧文（agy P2-5）——成立，一行删除
- v3 §5.1 重启恢复顺序仍写“执行恢复（重置峰值、清除 halt），再做当轮回撤检查”，与 §5.0(a)“恢复那一轮跳过 §5.1 检查”直接冲突。删去“再做当轮回撤检查”即可。
